# CV matching and application pipeline

The user requested ranked opportunities, clear match/missing-requirement/experience explanations, independent H-1B/OPT evidence and progression from saved review through application stages. This feature reuses the pinned career-ops evaluator and canonical tracker; it does not introduce a second scoring model or tracker.

Find jobs supports Save job or explicit Evaluate CV match (saves the authoritative posting, then queues evaluation). Saved jobs supports a single assessment or Compare selected roles, capped at three per click, and best-evaluated-profile sorting. The existing local Ollama worker runs these evaluations with the confirmed profile. Save/filter/sort never invokes AI. Queue serialization, daily job limits, recovery, cancellation and existing publication/fact/source boundaries remain. Cloud job discovery is independent and still works with the computer off; AI assessment and canonical tracker writes need the local worker online.

The server accepts only saved ID/revision, builds context from the server-owned immutable posting, and enqueues the existing evaluate operation with a deterministic key over saved source/profile draft/attempt. Active or successful current matches replay; failed/cancelled attempts can retry. A profile change yields a new profile-version key. Derivation reads only the caller’s exact posting URL and SHA-256 text context, using a bounded partial URL lookup index (019). Its index hash is an accelerator, not an identity/security check: exact source and actor checks remain. An existing bookmark with changed posting text returns a source conflict; remove that copy explicitly before saving/evaluating the updated posting, preserving prior evaluations and applications.

Scores come from published engine results, parsed only as valid 0–5 values. They are overall profile-fit judgments, not invented skill percentages or hiring probabilities. Current completed assessments sort first; stale/pending/failed/unrated sources do not gain a fabricated score. Confirmed-profile timestamp staleness is deliberately conservative. Match metadata is derived, not a new persisted personal-data table. It does not rewrite the CV, facts or old reports. Cross-tenant/other-requester evaluations cannot supply a score.

Why this match loads the authenticated, hash-checked report artifact on demand. Existing machine-summary and section/table parsers display evaluator strengths, missing/partial requirements, source evidence and experience/seniority. The report-owned summary parser avoids archived-JD spoofing; section excerpts stop before archived job text. All source/explanation text is escaped React text. Bare legacy Block B/C headings and plain-text requirement evidence are supported without changing the original report. Missing older summaries have explicit fallbacks and the original report remains available. H-1B/OPT posting evidence remains independently labeled; neither it nor a match score is a legal eligibility determination.

Applications adds a responsive board: Reviewing (saved and Evaluated/Speculative), Applied/screening (Applied/Responded/Assessment), Interviewing (Interview), Offer and Closed (Hired/Rejected/Discarded/SKIP). These are presentation groups over the existing statuses. Saved roles begin in Reviewing; Evaluate and add to tracker creates the canonical engine row. Later changes still use set_status with row hash/expected status and atomic snapshot publication. Applied requires the person to confirm actual submission. No application is sent by this feature. Manage stage links lead to the authoritative status controls, with search/filter and bounded card previews.

Validation: shared source-context parity, valid-score/rank/stage cases; real disposable Postgres source binding, concurrent replay, stale profiles/versioned retries, changed-JD refusal and role/revision boundaries; production Next/Playwright bounded comparison, ranking, explanation/table/experience rendering, archived-JD isolation, separate authorization and mobile; real native engine evaluate/PDF and Applied → Interview → Offer writes. Local full build/source/dependency audit and both typechecks passed. Live deployment/proof evidence is recorded in PROJECT_HANDOFF.md separately.
