# Hosted CV file import

Onboarding and My Profile editing now provide an Upload your CV file chooser. PDF, Word .docx, UTF-8/UTF-16 text and Markdown are supported up to 5 MB. Extraction fills the existing editable CV source field; the existing review/confirmation flow remains the publication boundary. No new upload API, Blob object type, model call, engine revision or database migration is introduced.

Original files are read in the browser. Selection/extraction does not save a draft or transmit file bytes. Existing review actions send extracted text: onboarding Review profile stores a draft, and confirmation publishes canonical source through the existing pipeline. A selected replacement overwrites the current editable text; errors preserve the previous text. Profile-edit cancellation preserves the confirmed source. Name/role/language are not inferred or overwritten by a parser.

The PDF parser uses pinned PDF.js 6.5.438 with a same-origin, build-emitted module worker, no external CDN, no scripting/eval, a 30-page limit and a 30-second extraction deadline. The actual Worker is required; fake-worker fallback refuses extraction. Password-protected, malformed or no-text/scanned PDFs produce actionable errors. OCR is not included.

Word uses pinned fflate 0.8.3 to select only document/header/footer XML; at most 2,000 archive entries, 16 selected XML parts and 2 MB of declared/actual extracted XML are accepted. Duplicate selected paths, complex/oversized XML, DTD/entities and malformed namespace/XML refuse extraction. Only paragraph text, tabs and breaks are read; macros, HTML, images, document links and actions are never rendered/executed. Older .doc requires conversion to .docx. Imported source is capped at the existing 200,000 characters plus a stricter encoded-size guard to fit the hosted JSON input limit.

The production build passed the route/source/dependency boundary audit (seven traces, about 7.4 MB of unique server dependencies). Hosted source preparation explicitly allowlists the shared component, styles and import module; parser libraries are lazy-loaded. No server-side filesystem/process route is added. Both web typechecks, hosted source-boundary tests, the text/file-bound unit test and the full disposable PostgreSQL suite passed. Production Next/Playwright tested real PDF worker extraction, Word body/header, text import, no POST on selection, unsupported/oversize/complex/DTD/no-text rejection, previous-text preservation, profile edit/cancel, and the existing onboarding/confirmation/reload/mobile/auth flow. npm audit reported zero hosted production dependency vulnerabilities.

Source CI, Vercel deployment and fresh synthetic production proof are recorded separately in PROJECT_HANDOFF.md. No real CV is a test fixture, and raw filenames/content/credentials are not logged or committed.
