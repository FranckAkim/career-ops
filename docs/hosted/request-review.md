# Interrupted-request review boundary

Migration 010 records deployment and application-runtime instance identity on new request markers. Hosted code obtains the deployment ID from Vercel's server environment and generates the instance UUID internally; clients cannot select either through an API request. Missing identity remains unknown. Existing records are not backfilled with invented provenance. The instance UUID is an application correlation value, not a provider execution identifier or termination certificate. See [Vercel system variables](https://vercel.com/docs/environment-variables/system-environment-variables#vercel_deployment_id).

`RequestReview` is an operator-only capability with no public route. Preview requires an active reviewed account block and returns a bounded activity list, unknown-identity count and exact review hash. Resolution requires explicit acknowledgement, a selected request from that scope, an evidence digest and a trusted termination verifier. The verifier must establish actual termination and return evidence bound to that activity, deployment, instance and digest. Provider errors, unknown identities and mismatched evidence refuse resolution. The module supplies no Vercel termination-evidence adapter and must not be configured with an unconditional success callback in production.

Verification occurs outside the database transaction, then the reviewed scope is checked again under the account/request locks. If a request settles, a block is cancelled or the purge phase changes during verification, the review becomes stale. Successful resolution atomically writes an opaque audit receipt and marks only the selected activity `terminated`. Runtime roles cannot access or write the receipt table; a web-role attempt to mark termination is denied. Normal response completion remains `settled`, preserving the distinction.

The receipt contains opaque identifiers, hashes and a verification timestamp, not raw provider logs, credentials, request payloads or evidence documents. It remains part of the minimal security audit after app-data cleanup. Evidence documents must remain in the operator's protected evidence system; this module does not upload or expose them.

An empty active list, an old timestamp, READY deployment status or deployment identity alone never establishes coverage of old/untracked deployments. Reports always return `deploymentCoverageVerified: false`. Public deletion stays unavailable until actual provider evidence/correlation and complete deployment coverage are verified. Real accounts and both unattributed historical snapshot groups remain untouched.

## Verification

Disposable PostgreSQL tests launch a real isolated child process, refuse resolution while it is alive, terminate and await its exit, and then resolve only its bound synthetic marker. Tests also cover unknown identity, missing confirmation, stale scope, foreign-instance evidence, sanitized verifier errors, runtime-role denial, missing receipts, atomic rollback and audit retention. This proves the local capability contract; it is not evidence of Vercel execution termination. Production identity evidence is recorded in `PROJECT_HANDOFF.md`.
