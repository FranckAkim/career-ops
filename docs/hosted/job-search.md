# Hosted job discovery

Opportunities now includes Find jobs. The first source is Himalayas remote jobs, with United States plus worldwide selected by default, a worldwide-only option, keyword/title search, experience filters and previous/next pages. This is remote-only coverage, not a complete US/on-site/hybrid search. No paid integration or API key is required for the initial public endpoint.

The authenticated GET /api/hosted/tenants/:tenantId/discover route checks origin, account lifecycle, request tracking and tenant membership through the existing control plane before querying the provider. Only validated q/country/page/seniority filters reach the fixed HTTPS search endpoint. Cookies, identity, CVs, workspace paths and arbitrary URLs do not. No migration or additional public route is added. HTML descriptions become bounded plain text and render as React text; links are restricted to HTTPS Himalayas company listings. Source attribution and the provider applicationLink are displayed unchanged. Expired jobs are discarded on response/cache reads and periodically in the displayed list. A listing may close early, so users must check the source and requirements.

Provider I/O has a 12-second timeout, a 3 MB streamed body cap, bounded result/string sizes, at most four distinct pending requests, identical-request coalescing, 32-entry/10-minute instance cache, 30 uncached requests/minute/instance and a one-minute provider-429 cooldown. These are per-instance resource controls, not a global distributed quota. Provider errors are sanitized; stale cached data is not served after cache expiry. Next-page controls continue until an empty provider page or the bounded page-50 ceiling; source results may shift between pages.

Use this job explicitly replaces the editable posting text/reference and focuses the existing evaluation form. It does not enqueue, persist a job or submit an application. Evaluate posting remains the explicit action through the existing queue/engine. Existing manually pasted descriptions still work. Source links and Apply on Himalayas open external pages; nothing is sent automatically. Search keywords/filters are disclosed in the privacy page. No engine/local-worker revision, cloud AI, raw CV transmission or storage-token change is needed.

Validation: 51 control-plane unit checks pass, including real auth/tenant denial before provider contact, filter rejection, safe links, expired/duplicate records, HTML-to-text, bounded provider bodies, cache/coalescing and sanitized rate-limit/failure behavior. Both web typechecks, hosted source tests, production build/boundary audit and full disposable PostgreSQL + production Next/Playwright pass. The browser proof covers US query, source/application links, explicit import with zero POSTs, pagination, empty/failure preservation and mobile overflow. A real public provider adapter request returned 20 normalized US-search results. Deployment/live verification is recorded in PROJECT_HANDOFF.md, separately from local evidence.
