# Built-in hosted/local job discovery

Current design replaces the earlier Himalayas-only integration with the repo's real scan-ats-full.mjs scanner. Opportunities queues an authenticated search; a separate on-demand local discovery worker runs the scanner, and the app polls for results. Greenhouse, Lever, Ashby and Workday are the same four ATS sources exposed by the repo's Explore scanner. No AI/search API key is needed for these public-board requests. The user prioritizes the United States; location keywords remain editable. Keyword comma lists, recency and board sampling use the existing portals serializer and scannerArgs helper. Work-arrangement filtering uses scan.mjs buildWorkplaceFilter; unknown types are excluded when a specific type is selected. No scoring/tracker/CV rules are reimplemented.

Discovery uses a dedicated ephemeral discovery_runs queue (migration 015), not the mutation/AI job queue. Auth, same-origin checks, tenant membership, lifecycle guards and request tracking stay inside the existing catch-all API. POST discovery validates only q/location/workplace/sinceDays/limitPerAts; GET latest or an exact request and POST cancellation require the requesting user/tenant. Search is limited to one active request per tenant/user and ten per tenant/hour. Identical active input replays the same request; conflicting active input returns 409. Cancel and account block prevent late publication. Claims are atomic and token-bound; expired leases become failed rather than silently repeating a scan. Heartbeat loss cancels the local child. Search state/results expire after 24 hours and worker cleanup removes expired rows. Data export includes currently retained discovery metadata/results; blocking removes them atomically, and tenant deletion cascades them.

The local worker uses the restricted career_worker role. It receives filters only, never a CV/snapshot or auth/AI keys. Each child gets a new mkdtemp data root and generated ephemeral filters/profile, a fixed executable/script and bounded allowlisted arguments, no shell or inherited credential environment. --dry-run prevents pipeline/tracker/history changes; scanner cache writes stay in that exact scratch folder. Cleanup verifies the absolute folder stays directly beneath the private work root and waits for the child to close. Crashed/abandoned scratch folders remain an operator-review concern and block local purge drain; never clear them merely from age. No privileged service, public local listener, browser debugging, logon trigger or cloud AI worker is added.

A small opt-in --include-descriptions extension adds bounded description, truncation and work-arrangement metadata to the core scanner JSON receipt. Default JSON behavior remains unchanged. Truncated/missing descriptions disable Use this job; users can open the employer posting. Complete descriptions populate the existing review/evaluation form; evaluation still requires a separate click. Nothing applies automatically. This extension is for the host scanner; the isolated CV/evaluation engine image remains pinned unchanged.

Coverage is explicitly partial when the scanner reports a cap, unavailable/stale source, missing dates, inaccessible boards, interruption or timeout. There is a four-minute child limit, 8 MB stdout cap, at most 50 displayed matches and a 2 MB normalized-results cap. Core transport DNS/IP/redirect and per-source request safeguards remain in effect. Location text is matching evidence, not proof of citizenship/visa eligibility. Always check the employer posting. Local inference and discovery are independent tasks; both need the computer awake for work to run. A broad sample can take minutes and does not represent the entire US market.
