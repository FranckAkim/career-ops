## Review states, availability and live progress (24 November 2026)

Search cards offer Mark seen, Mark new, Dismiss job and Restore job. The Review status filter hides explicitly dismissed jobs by default, with All/New/Seen/Dismissed options. Choices persist across searches without consuming bookmark slots (500-role history); Manage job review history requires an explicit reset acknowledgement. Saved jobs use the same state. Version tokens reject stale concurrent writes, and resetting review history preserves saved postings, notes and canonical application stages. Legacy saved review choices are retained.

Saved jobs → Check availability runs the existing core ATS API liveness rung through the cloud queue, with no CV, model, browser fallback or tracker mutation. The worker claims only the stored exact ATS posting URL/provider; browser-supplied URLs/commands and Handshake automatic checks are refused. Confirmed API removal is distinct from inconclusive evidence: blocked requests, timeouts, unsupported providers and non-authoritative missing responses remain unconfirmed (including Lever404). The result is a timestamped observation, not a guarantee of future availability. Some of the seven discovery networks lack a conclusive API rung; use the original posting and Record my manual check. Manual checks require acknowledgement and are labeled as the user's statement. Handshake always uses that manual route and never accesses the student account.

A complete description for the same URL in the latest retained owned search can flag changed requirements. The saved source and its evaluation stay immutable. Availability alone does not refresh description, compensation, authorization evidence or CV matching; review and save the current posting before evaluating changed requirements.

An active search reports actual per-provider queued/running/finished/failed/timed-out states and a completed-source progress bar. Per-source match/board counts are before final merge, not overall job counts. These updates come from the existing two-source scheduler; no percent-of-jobs estimate or extra crawl is added. Progress delivery is best effort; heartbeat/claim/cancellation/publication fences remain authoritative.

Follow-up drafts retain their editing revision and unsaved text across background metadata updates. A conflicting save preserves edits; only Reload saved plan (discard edits) replaces the draft. Review-state synchronization invalidates stale saved-note forms rather than overwriting a newer state.

Migrations022-024 add bounded availability metadata, private review history and token-bound progress. Discovery still has no saved-job/review table SELECT grant; its exact claim capability returns only the URL/provider needed for a check. Web has no progress-write/private-RPC grant. Export includes availability/review/progress, deletion scope binds review versions, and account purge removes metadata through tenant cascades. All75 unit tests,11 scanner cases,five worker checks,both refreshed-package production builds/audits/typechecks and the complete disposable PostgreSQL/production Next/Playwright/native engine/PDF regression pass. Browser tests exercise real queue/database progress, state persistence/sync/reset, explicit manual provenance, note-conflict preservation/discard and mobile layouts. Production rollout/evidence is tracked in PROJECT_HANDOFF.md.


## Saved searches and in-app alerts (24 November 2026)

Find jobs → Saved searches & alerts saves the current validated filter set under a name (five per account). Run starts the normal discovery queue; View latest results restores its filters and opens the owned retained run. Removing a saved search prevents future daily checks; it does not cancel an already queued scan. Search results still expire after 24 hours. The latest summary and saved filters persist until removal/account deletion.

Daily checks are explicit opt-in, paused by default. The existing 06:00 UTC cron dispatches due searches through career-discovery; consumer completion dispatches the remaining due work, preserving one active search per account and the existing ten-search hourly limit. Scans can be delayed by queue capacity, active searches or rate limits. A paused schedule is not automatically resumed. No email, employer message, CV access, evaluation, new inference provider or additional service is involved.

Migration 021 adds private saved_searches with membership/lifecycle guards, tenant-row serialization, immutable input and revisioned edits. The career_discovery role gets only a scheduler RPC returning opaque run IDs, no table/CV read privileges. Concurrent ticks create one run; queued notification recovery reuses queue idempotency and token-bound discovery claims. Completion atomically records the latest successful count, count of URLs absent from the previous successful result sample, partial-coverage flag and unread status. Failures/cancellation remain explicit and never become a successful zero count; the previous successful URL sample is retained for the next comparison. These counts do not establish that a job was newly published or cover all employer postings.

Private export includes saved searches/summary/baseline URLs. Operator and recent-auth public deletion scope include saved-search revisions; mutations invalidate stale review. Account blocking prevents schedule writes/publication, and tenant deletion cascades the saved rows. The original private deletion-scope RPC identity/grants are preserved when extending its scope.

Validation: 71 unit tests, both production builds/typecheck, five worker checks and full disposable PostgreSQL/production Next/Playwright/native engine/PDF suite pass. Tests cover concurrent scheduler/replay, owner and stale-revision denial, new-URL comparison, failure disclosure, quota, explicit browser consent, pause/resume/read/view/removal/mobile, export and deletion guards/final purge. Production rollout/live proof evidence is in PROJECT_HANDOFF.md. Wall-clock cron execution must not be inferred solely from these tests.


## Workflow upgrades (23 November 2026)

Find jobs → Advanced job targeting offers experience, employment type, minimum annual USD salary, exact employer exclusions and literal negative phrases. Controls are explicit and restored with the search. Missing evidence is retained; a salary in another currency is not converted or excluded. Experience is title evidence, not an inferred years-of-experience claim. The existing source/date/link gates and label-first visa defaults remain. Finished results show per-source timings and targeting exclusion counts; this is completed-run diagnostics, not live provider progress.

Saved jobs → Review state & follow-up plan stores new/seen/dismissed, applied date, deadline, follow-up date, contact, next action and private notes. Save is explicit; edits use the current saved-job revision to reject concurrent overwrites. Notes are included in the private account export and removed with their saved row/account. Recording an application date never submits an application or writes a canonical status. These review states currently cover saved jobs only. A past follow-up date does not send messages or automatically contact an employer.

Compare selected roles keeps up to three selections visible during/after evaluation, showing completed current-profile assessments and existing report-owned strengths/gaps side by side. Removed jobs drop out of selection; changed-profile evaluations do not count as current completed matches. The engine and original authenticated report remain authoritative.

Migration 020 adds only the saved_jobs workflow column and narrow career_web update grant. Discovery has no access to those notes. Existing row revision binds deletion-review scope; existing deletion removes this metadata. Full disposable PostgreSQL/production Next/Playwright/native engine and PDF checks pass, including note reload, state filtering, conflict/owner refusal, export and canonical tracker behavior. Seventy unit tests, both builds and five worker checks pass.

Remaining from the approved upgrade program: durable saved searches/daily in-app alerts, review states for unsaved discovery results, safe saved ATS availability rechecks (Handshake manual), and live source progress. These are not shipped by this release.

The local worker uses the restricted career_worker role. It receives filters only, never a CV/snapshot or auth/AI keys. Cleanup verifies the absolute folder stays directly beneath the private work root and waits for the child to close. Crashed/abandoned scratch folders remain an operator-review concern and block local purge drain; never clear them merely from age. No privileged service, public local listener, browser debugging, logon trigger or cloud AI worker is added.

A small opt-in --include-descriptions extension adds bounded description, truncation and work-arrangement metadata to the core scanner JSON receipt. Default JSON behavior remains unchanged. Truncated/missing descriptions disable Use this job; users can open the employer posting. Complete descriptions populate the existing review/evaluation form; evaluation still requires a separate click. Nothing applies automatically. This extension is for the host scanner; the isolated CV/evaluation engine image remains pinned unchanged.

Coverage is explicitly partial when the scanner reports a cap, unavailable/stale source, missing dates, inaccessible boards, interruption or timeout. There is a four-minute child limit, 8 MB stdout cap, at most 50 displayed matches and a 2 MB normalized-results cap. Core transport DNS/IP/redirect and per-source request safeguards remain in effect. Location text is matching evidence, not proof of citizenship/visa eligibility. Always check the employer posting. Local inference and discovery are independent tasks; both need the computer awake for work to run. A broad sample can take minutes and does not represent the entire US market.
