# Saved jobs and shortlists

Opportunities has Find jobs and Saved jobs views. Save job preserves a private immutable copy of a server-returned discovery result. Saved jobs remain after the 24-hour discovery cleanup, can be shortlisted or unshortlisted, and can fill the existing evaluation form with Use this saved job. Evaluation remains a separate action; nothing applies automatically. This is a bookmark list, not an application status or replacement for the canonical engine tracker.

Migration 016 adds saved_jobs with a tenant-cascade FK, exact-source-URL SHA-256 uniqueness, immutable posting content, a revision and shortlist flag. POST /api/hosted/tenants/:tenant/saved-jobs accepts only runId/jobId; the service looks up that exact signed-in user's unexpired successful run before copying bounded fields. Browser-supplied posting content/owner identity is rejected. Source URLs require HTTPS without credentials/ports; descriptions render as text. There are at most 30 saved postings per user/workspace, with 120 KB serialized source and 30,000-character description limits. Existing exact-URL saves replay the existing row without overwriting its snapshot or shortlist. Tenant-row locking serializes duplicate saves/quota checks and account review ordering.

GET lists only the current user's workspace bookmarks. POST :id/shortlist and :id/remove require the displayed revision; stale changes return 409 and refresh the list. Removal requires a separate inline confirmation in the UI, removes only the bookmark, and preserves evaluation history, CVs and applications. Incomplete descriptions can be saved/opened but cannot populate evaluation. Saved copies are historical: users must check the employer page for live availability and eligibility. A saved copy has no automatic expiry.

The web role can select/insert/delete and update only shortlisted; it cannot rewrite the posting, identity, revision or timestamps directly. The trigger makes identity/source/creation immutable, assigns revisions/timestamps and uses the existing account/workspace/membership guards. The worker role has no saved-job table access. Auth, same-origin checks, request draining, tenant/user checks and bounded JSON parsing use existing middleware. No API key, worker/model revision, canonical engine write or public local listener is introduced.

Workspace export includes saved posting snapshots, shortlist flags, revisions and dates. Recent-auth public deletion review includes a saved-job count and hashes their immutable identities/revisions/shortlist state; changing the list invalidates a stale review. The private operator scope mirrors this. Blocking preserves saved content for operator review and refuses further changes; physical tenant removal cascades the rows. Existing purge/fence grants are unchanged.
