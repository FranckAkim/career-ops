# H-1B and OPT discovery filters

Find jobs now offers Any policy, H-1B sponsorship/transfers, OPT/STEM OPT acceptance, H-1B or OPT, and H-1B and OPT. Include unclear work-authorization policies is opt-in and defaults off. Filters restore from the last discovery request. They are search preferences, not candidate facts, and never update the confirmed CV/profile.

The existing ATS scanner, transport and title/location/workplace rules remain authoritative. Its opt-in --include-descriptions receipt now also carries bounded visaText (4,000 characters), so the local discovery wrapper uses the existing scan.mjs visaFilterText function to include provider policy metadata outside the description. The repo's broad visa_filter vocabulary cannot distinguish an H-1B mention from sponsorship or OPT acceptance, so the hosted integration adds a narrow, pure, deterministic evidence classifier rather than presenting broad visa matches as verified support.

classifyWorkAuthorization has versioned positive/negative/unknown/conflicting states for H-1B and OPT independently. It requires affirmative sponsorship/transfer wording for an H-1B positive, and explicit acceptance/applicant wording for OPT. Bare mentions, H-1B1, E-Verify alone, generic work authorization, questions and ordinary opt-in/opt-for prose are not positive evidence. Generic explicit sponsorship refusals apply to H-1B, not automatically to OPT. Citizenship-only restrictions apply to both. Recognized opposing statements across clauses produce conflicting evidence; it never satisfies that requirement, even when unclear policies are included. Truncated/missing descriptions cannot establish positive support. Up to three normalized, bounded source snippets per category explain the result.

The worker gate applies the requested category after existing workplace matching and before the bounded result list. Either keeps a qualifying category; Both requires both. The unknown option admits unknown categories but never turns a recognized negative/conflict into a match. A source can accept OPT and refuse sponsorship; OPT acceptance does not establish future H-1B sponsorship. Positive wording is not a legal/employer eligibility determination, and transfer/STEM restrictions must be checked in the actual posting. No historical sponsorship database, new employer verification, or immigration advice is represented by these labels.

discoveryInput validates authorization in any/h1b/opt/either/both and a boolean includeUnknown, with backward-compatible defaults for earlier JSON requests. API body fields remain allowlisted. No schema migration is needed. Results carry policy states/snippets, filter metadata and a rejected-posting count. UI renders evidence as text and displays unknown/not-assessed states instead of inventing eligibility. SavedJobs recomputes evidence from the immutable server-owned description/visaText; browser-supplied labels are ignored. New saved copies retain source policy metadata, export includes it and existing account-review/purge controls apply unchanged. Old saved copies are not rewritten and can display not assessed.

Source policy metadata is included when explicitly loading a posting for evaluation, so source evidence is not lost when it was supplied outside the JD body. This still requires the user's Evaluate posting click. No model call, CV transmission, worker secret, API key, new public route, paid provider or application submission is added.
